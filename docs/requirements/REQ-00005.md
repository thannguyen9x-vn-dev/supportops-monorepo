## 2. Context & Background

- **Module liên quan:** Requests (CRUD) — hiện đang 🔶 In Progress
- **Trạng thái hiện tại:** ❌ Chưa có bất kỳ endpoint/logic import nào trong `apps/api` hay `apps/ai-service`
- **Context export hiện tại:**
  - `apps/ai-service` đã có: `POST /export/csv`, `POST /export/excel`, `POST /export/pdf`
  - Export được trigger từ `apps/api` → `ai-service` (internal service call)
- **Constraint:**
  - Multi-tenant: mọi request import phải được scope theo `tenantId` từ JWT
  - RBAC: chỉ `OPS_COORDINATOR` và `TENANT_ADMIN` mới được phép bulk import
  - `tenantId` không được nhận từ file upload — luôn lấy từ JWT claims
  - File import được xử lý qua MinIO (S3-compatible) để tránh upload trực tiếp vào memory

## 3. Phương Án Import — Phân Tích So Sánh

> **Lưu ý cho PO:** Đây là phần phân tích các phương án. Hãy chọn **1 hoặc kết hợp** trước khi proceed.

### Phương án A — CSV/Excel Bulk Import (Template-based)

**Mô tả:** PO/Coordinator tải về template CSV/Excel chuẩn, điền dữ liệu request, upload lại. Hệ thống parse và tạo nhiều request một lúc.

**Flow:**
```
User tải template → Điền dữ liệu → Upload file → Validate → Preview → Confirm → Tạo requests
```

**Ưu điểm:**
- Phù hợp với team không technical (Excel quen thuộc)
- Dễ migrate dữ liệu từ spreadsheet cũ
- Preview trước khi commit → ít lỗi

**Nhược điểm:**
- Cần định nghĩa template chặt (column names, format ngày, enum values)
- Validation phức tạp (service type hợp lệ? user tồn tại trong tenant?)
- File lớn có thể timeout → cần async processing

**Độ phức tạp:** Medium (3–5 ngày dev)

---

### Phương án B — JSON API Bulk Import

**Mô tả:** Cung cấp endpoint `POST /requests/bulk` nhận array JSON (tối đa N items). Dành cho integration với hệ thống khác (ERP, HRMS).

**Flow:**
```
External system → POST /api/requests/bulk (JSON array) → Validate → Tạo requests → Return summary
```

**Ưu điểm:**
- Phù hợp tích hợp hệ thống (automation, webhooks)
- Đơn giản nhất để implement (không cần parse file)
- Dễ test

**Nhược điểm:**
- Không có UI → không phù hợp cho end-user manual import
- Cần API key / service account management nếu external system gọi trực tiếp

**Độ phức tạp:** Low (1–2 ngày dev)

---

### Phương án C — Migration Import từ Hệ Thống Ngoài

**Mô tả:** Wizard import có mapping field linh hoạt. User upload file từ Jira, ServiceNow, Zendesk (export CSV của họ) → Hệ thống hiển thị mapping UI → Confirm → Import.

**Flow:**
```
Upload file (bất kỳ format) → Detect columns → Map columns → Validate → Preview → Import
```

**Ưu điểm:**
- Linh hoạt nhất cho migration project
- Không yêu cầu user format lại file

**Nhược điểm:**
- Phức tạp nhất (cần mapping UI)
- Out of scope cho MVP
- Cần nhiều edge case handling

**Độ phức tạp:** High (2–3 tuần dev)

---

### Phương án D — Import via Webhook / Event Stream (Async)

**Mô tả:** Hệ thống lắng nghe event từ external source (email, webhook URL). Mỗi event tạo 1 request mới tự động.

**Flow:**
```
External event (email/webhook) → Worker parse → Validate → Tạo request → Notify assignee
```

**Ưu điểm:**
- Tự động hoàn toàn
- Phù hợp cho ticketing từ email (IT helpdesk classic)

**Nhược điểm:**
- Phụ thuộc `apps/worker` (hiện là ❌ TODO)
- Scope rất lớn, nhiều security considerations
- Cần email server / webhook management

**Độ phức tạp:** Very High — **không khuyến nghị cho MVP**

---

### Khuyến nghị của BA

**Cho MVP (ngắn hạn):** Chọn **Phương án A** (CSV/Excel template-based) kết hợp với **Phương án B** (JSON bulk API).
- Phương án A phục vụ end-user (Coordinator import hàng loạt)
- Phương án B phục vụ integration sau này (technical consumers)

**Phương án C và D** nên để Roadmap sau MVP.

## 4. Detailed Requirements (Dựa trên Phương án A + B được khuyến nghị)

### 4.1 Functional Requirements

| ID | Requirement | Priority | Phương án |
|---|---|---|---|
| FR-001 | TENANT_ADMIN và OPS_COORDINATOR có thể tải về file template CSV/Excel chuẩn của tenant | Must Have | A |
| FR-002 | User upload file CSV/Excel (≤ 5MB, ≤ 500 rows) và hệ thống parse ra preview | Must Have | A |
| FR-003 | Preview hiển thị danh sách rows sẽ được tạo, rows lỗi được highlight kèm lý do | Must Have | A |
| FR-004 | Sau khi confirm, hệ thống tạo các request hợp lệ; rows lỗi bị skip và báo cáo | Must Have | A |
| FR-005 | Import result trả về: số thành công, số lỗi, danh sách lỗi kèm row number | Must Have | A |
| FR-006 | Template CSV/Excel có columns: title, description, serviceTypeCode, priority, locationId, dueDate, reporterEmail | Must Have | A |
| FR-007 | Validate: serviceTypeCode phải tồn tại trong tenant; priority phải thuộc enum hợp lệ | Must Have | A |
| FR-008 | Validate: reporterEmail (nếu có) phải là member trong tenant | Should Have | A |
| FR-009 | Endpoint `POST /requests/bulk` nhận JSON array (max 100 items), tạo requests theo batch | Must Have | B |
| FR-010 | Bulk API trả về summary: `{ created: N, failed: N, errors: [{index, message}] }` | Must Have | B |
| FR-011 | File import lớn (> 100 rows) được xử lý async qua BullMQ worker; user nhận thông báo (in-app / toast) khi job hoàn tất | Must Have | A |
| FR-012 | Import log được lưu lại (ai import, khi nào, bao nhiêu records) cho audit | Should Have | A+B |

### 4.2 Non-Functional Requirements

| ID | Requirement |
|---|---|
| NFR-001 | File upload qua MinIO (không lưu trực tiếp trên server) |
| NFR-002 | tenantId luôn lấy từ JWT claims — không tin dữ liệu trong file |
| NFR-003 | Bulk API rate limit: 10 requests/phút per tenant |
| NFR-004 | Tất cả import (dù nhỏ hay lớn) đều xử lý async qua BullMQ job queue — API trả về `jobId` ngay lập tức |
| NFR-005 | Validation errors phải rõ ràng: "Row 5: serviceTypeCode 'IT_UNKNOWN' không tồn tại trong tenant" |
| NFR-006 | RBAC guard: chỉ OPS_COORDINATOR và TENANT_ADMIN mới có permission `request.import` |
| NFR-007 | pnpm typecheck pass, pnpm lint pass |
| NFR-008 | Tất cả UI text có trong en.json + vi.json |

## 5. Acceptance Criteria

- [ ] AC-001: EMPLOYEE không thể truy cập trang import (403 khi gọi API)
- [ ] AC-002: OPS_COORDINATOR và TENANT_ADMIN thấy nút "Import" trên trang Requests List
- [ ] AC-003: Download template CSV chứa đúng các columns theo spec FR-006, có 1 row ví dụ
- [ ] AC-004: Upload file CSV hợp lệ (< 5MB, ≤ 500 rows) → hiển thị preview table
- [ ] AC-005: Row với serviceTypeCode không hợp lệ → highlighted đỏ trong preview, kèm message rõ ràng
- [ ] AC-006: Confirm import → rows hợp lệ được tạo thành ServiceRequest với đúng tenantId từ JWT
- [ ] AC-007: Import result modal hiển thị: X requests tạo thành công, Y rows lỗi (kèm chi tiết)
- [ ] AC-008: File > 5MB → rejected với error message trước khi upload lên server
- [ ] AC-009: `POST /requests/bulk` với 3 items hợp lệ → 3 requests được tạo, trả về `{ created: 3, failed: 0 }`
- [ ] AC-010: `POST /requests/bulk` với item thiếu `title` → item đó trả về lỗi, các item khác vẫn được tạo
- [ ] AC-011: Sau khi upload file → API trả về `{ jobId, status: "queued" }` ngay lập tức (không block)
- [ ] AC-011b: Worker xử lý job trong nền; khi xong user nhận notification với kết quả (success/fail count)
- [ ] AC-011c: Import audit log ghi nhận: userId, tenantId, timestamp, totalRows, successCount, failCount
- [ ] AC-012: `pnpm typecheck` pass trên toàn monorepo
- [ ] AC-013: `pnpm lint` pass trên toàn monorepo
- [ ] AC-014: i18n — tất cả UI text import có trong `en.json` và `vi.json`

## 6. Scope Boundaries

**IN SCOPE:**
- Template download (CSV + Excel format)
- File upload + parse (CSV, .xlsx)
- Preview + validation UI
- Confirm + import flow
- Import result summary
- `POST /requests/bulk` JSON API endpoint
- Import audit log (basic: ai, khi nào, bao nhiêu)
- RBAC guard cho tất cả import endpoints

**OUT OF SCOPE (không làm trong task này):**
- Migration wizard với flexible column mapping (Phương án C)
- Webhook / email-based auto import (Phương án D)
- Import các entity khác (users, service types, SLA policies)
- Real-time progress bar (WebSocket polling) — async notification là đủ
- Deduplication logic (tránh tạo duplicate requests)
- Rollback / undo import
- Worker setup nếu chưa có — **worker phải được khởi tạo trước đây là dependency cứng**

## 9. Risks

| Risk | Mức độ | Mitigation |
|---|---|---|
| File parse sai format gây crash service | High | Validate file type + size trước khi parse; try/catch với error boundary |
| User import duplicate requests (cùng title + serviceType + ngày) | Medium | Thêm warning trong preview nếu phát hiện potential duplicate; dedup là out of scope cho lần đầu |
| tenantId bị inject qua file (security) | High | **Luôn** lấy tenantId từ JWT, không bao giờ đọc từ file |
| File quá lớn gây memory spike trên api server | Medium | Stream parse (csv-parse, exceljs streaming mode); limit 5MB + 500 rows |
| **`apps/worker` chưa có code thật** — đây là dependency cứng cho async | **High** | Worker phải được setup (BullMQ + Redis) trước khi bắt đầu import feature. Đề nghị tạo DESIGN riêng cho worker bootstrap. |
| ServiceType code thay đổi sau khi user tải template | Low | Template nên include comment/note về valid codes; validate tại thời điểm import |
