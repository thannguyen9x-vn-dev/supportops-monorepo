## 1. Brief Requirement (Input từ PO)

> Dashboard hiện là ecommerce template placeholder (`todaySales`, `todayVisitors`...). Cần viết lại hoàn toàn cho ServiceOps context — hiển thị KPI vận hành thực tế cho team Ops.

---

## 2. Context & Background

- **Module liên quan:** Dashboard (`apps/web/src/app/.../dashboard/`)
- **Trạng thái hiện tại:** ❌ Template placeholder — i18n keys là ecommerce, không có data thật
- **Constraint:**
  - Multi-tenant: mọi query phải filter theo `tenantId`
  - RBAC: tất cả roles đều xem được dashboard, nhưng data scope khác nhau:
    - `EMPLOYEE`: chỉ thấy requests của chính mình
    - `TECHNICIAN`: thấy requests được assign cho mình
    - `OPS_COORDINATOR` + `TENANT_ADMIN`: thấy toàn bộ tenant
  - Không cần real-time (WebSocket) — load khi vào trang, refresh thủ công là đủ cho MVP dashboard
  - Không tạo DB table mới — aggregate từ `ServiceRequest` + `SlaRecord` hiện có

## 3. Detailed Requirements

### 3.1 Functional Requirements

| ID | Requirement | Priority |
|---|---|---|
| FR-001 | KPI cards: Open Requests, In Progress, Resolved Today, Overdue (SLA Breached) | Must Have |

| FR-003 | Breakdown requests by status (bar chart hoặc donut) | Must Have |

| FR-005 | Recent requests table (10 rows mới nhất, link đến detail) | Must Have |

| FR-007 | Filter theo time range: Today / This Week / This Month | Should Have |
| FR-008 | Loading skeleton khi data đang fetch | Must Have |
| FR-009 | Empty state khi chưa có data | Must Have |
| FR-010 | Error state khi API fail | Must Have |

| ID | Requirement |
|---|---|

## 5. Scope Boundaries

**IN SCOPE:**
- Rewrite toàn bộ dashboard page
- 1 API endpoint tổng hợp KPI data
- Recent requests table (read-only, không action)
- Time range filter (Today / This Week / This Month)
- Loading / empty / error states

**OUT OF SCOPE (không làm trong task này):**
- Real-time updates / WebSocket
- Export data (CSV/PDF)
- Drill-down charts (click vào chart → filter list)
- Team workload comparison giữa các members
- Notification bell / alerts
- Worker background aggregation job (Phase 3)

## 8. Risks

| Risk | Mức độ | Mitigation |
|---|---|---|
| Aggregation query chậm nếu nhiều requests | Med | Dùng `groupBy` + `count` thay vì fetch all rồi count ở app layer |
| i18n keys cũ bị bỏ sót (ecommerce keys) | Low | Grep toàn bộ `dashboard` namespace trước khi xong |
| RBAC scoping phức tạp (4 roles, 3 data scopes) | Med | Implement server-side filtering rõ ràng theo role, test từng case |
