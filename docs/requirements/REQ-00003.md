## 0. Brief Requirement (Input từ PO)

> TENANT_ADMIN cần có một AI Assistant trong dashboard để hỏi và tổng hợp thông tin vận hành dự án bằng ngôn ngữ tự nhiên. AI tự hiểu khoảng thời gian từ câu hỏi, nếu không rõ thì hỏi lại trước khi truy vấn. TENANT_ADMIN có thể chọn model AI mong muốn — cài default trong Settings và override per-session trong chat panel. Hỗ trợ cả Anthropic và OpenAI models.

---

## 1. Context & Background

- **Module liên quan:** Dashboard (`apps/web`) + AI Service mới (`apps/ai-service` — Python/FastAPI) + Settings
- **Trạng thái hiện tại:** Chưa có AI feature nào trong codebase trước V3.1
- **Constraints:**
  - Multi-tenant: AI Service chỉ được truy vấn data của đúng `tenantId` từ JWT — không tin user input
  - RBAC: **chỉ `TENANT_ADMIN`** được dùng AI Chat — 403 với mọi role khác
  - AI Service là **read-only** — không có quyền INSERT/UPDATE/DELETE vào DB
  - `apps/ai-service` là **Python app độc lập**, không nằm trong pnpm workspace
  - NestJS đóng vai proxy: verify JWT → inject `tenantId` → forward sang FastAPI
  - AI Service deploy **cùng server** với NestJS — gọi qua `localhost` hoặc internal network
  - Không thêm package mới vào `packages/` (đóng băng theo TASK 3.2)
  - 2 API keys (Anthropic + OpenAI) chỉ lưu trong env của AI Service — không vào DB, không trả về FE

## 5. Scope Boundaries

### IN SCOPE (đã implement)
- AI Chat panel UI trong dashboard (chỉ TENANT_ADMIN thấy)
- NestJS proxy endpoint `POST /api/v1/ai/ask`
- NestJS endpoint `GET/PATCH /api/v1/ai/settings` — lưu model preference per tenant
- `apps/ai-service` — Python FastAPI service mới, độc lập
- Claude tool use / OpenAI function calling: `get_report_data(tenantId, fromDate, toDate, metrics[])`
- Các metric AI có thể trả lời: request volume, status counts, SLA health, top technicians, service type breakdown
- Conversation history trong session (không persist vào DB)
- Model selection: Settings page (default) + chat panel dropdown (per-session override)
- Adapter pattern trong AI Service: 1 interface, 2 implementation (Anthropic + OpenAI)
- Deploy: cùng server, giao tiếp qua localhost

### OUT OF SCOPE (không làm trong V3.1)
- Streaming response (FR-006 — để V3.2)
- Lưu conversation history vào DB
- Export / download chat history
- AI gợi ý hoặc thực hiện action (assign request, đổi SLA...) — chỉ read và answer
- Text-to-SQL tự do — chỉ dùng predefined tool/function
- Voice input
- AI cho các role khác ngoài TENANT_ADMIN
- Training hoặc fine-tune model
- Thêm model provider mới ngoài Anthropic + OpenAI
- Rate limiting (không giới hạn cho V3.1)
- Audit log câu hỏi / câu trả lời

## 8. Risks

| Risk | Mức độ | Mitigation |
|---|---|---|
| tenantId isolation bị bypass nếu AI Service không validate đúng | **High** | NestJS inject tenantId vào header sau khi verify JWT — AI Service chỉ dùng tenantId từ header ✅ |
| 2 API keys bị expose | **High** | Keys chỉ nằm trong env của AI Service, không trả về FE hay log ✅ |
| AI hallucinate số liệu | **Med** | Dùng tool use / function calling — AI chỉ diễn giải data thật từ DB ✅ |
| AI Service down làm ảnh hưởng toàn dashboard | **Low** | NestJS catch lỗi, FE hiện degraded state — chat panel disabled nhưng dashboard KPI vẫn hoạt động ✅ |
| Cost không kiểm soát nếu admin dùng Opus liên tục | **Low** | Label rõ ràng bên cạnh model name ✅ |
| OpenAI API format khác Anthropic | **Med** | Adapter pattern — 1 interface, 2 implementation riêng biệt ✅ |
| Prisma migration thêm `TenantAiSettings` | **Low** | Migration nhỏ, không ảnh hưởng data hiện có ✅ |

## 9. Deploy Notes

### Environment variables cần thêm

**`apps/ai-service/.env`:**
```env
ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...
DATABASE_URL=postgresql://...
PORT=8000
```

**`apps/api/.env`:**
```env
AI_SERVICE_URL=http://ai-service:8000   # production
AI_SERVICE_URL=http://localhost:8000    # local dev
```

### Chạy AI Service locally
```bash
cd apps/ai-service
pip install -r requirements.txt
cp .env.example .env   # điền API keys
uvicorn main:app --reload --port 8000
```
